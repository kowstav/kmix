# Clean markup, persistent title memory and controlled retrieval

Registered6October2026 after finding a semantic defect in the old ASCII observer. That observer commits words inside XML tags while its title flag is active; `title` consequently enters many article title-key sets. This is causal and normalized, but makes a purported semantic title match unreliable. The prior experiment remains a valid test of its exact noisy signal, not a clean title-retrieval result.

Build a causal quote-aware XML observer. Skip words inside tags and metadata fields; learn lexical counts/transitions only in title or text. Enter/exit fields after their complete observed tags. Decode common XML entities into lexical characters only after the entity is fully observed. Unknown entities create a boundary; no external parser/model is shipped. ASCII lexical coverage is explicit; literal/Unicode/fallback bits remain paid by the native coder. Do not flush unfinished words, entities or codes at EOF.

Use normalized dictionary-tree masses for: persistent exact current-title words; rank/length-matched random title words; integer-geometry neighbors of title words; title-key retrieved summaries of completed past articles; same-count random past summaries. Compare each paired with the clean constructor-run residual, plus a matched generic calibration arm. Only apply lexical source residuals inside decoded text; all other outcomes retain generic/neutral support. Share one parser and bounded bank; reconstruct source state from the prefix. Maximum1024 article rows,32 words per row,4 retrieved donors, existing4096 syntax rows and original dictionary tree bounds.

Use the already independently verified25-candidate context-tree gate. Fixed context partition now uses bit position, native uncertainty band, WRT parser state, punctuation, observed field role (other/title/text) and number of completed lexical events since page start (0–15,16–127,128–1023,1024+). The last variable tests persistence past the original128-event echo horizon; it is known before the target. The gate charges its own finite-model/tree prior as before. Track actual Q16 tax, baseline cost, every arm and matching random controls. No core weights or core updates change.

Before data, reproduce old tag contamination and assert its absence in the new observer; test quoted `>` attributes, entities, title/body transitions, completed-past bank, normalized masses, and unflushed EOF. A/B128KiB pilot: advance to full A/B/C/D2MB only if at least one actual title/geometry/retrieval arm exceeds BOTH generic calibration and its random control by64 bytes in combined256KiB, with a positive incremental sign in each pilot. Otherwise preserve a scientifically negative pilot and revise the signal; do not run more full native jobs for tiny fluctuations. The threshold is a resource gate, not a proof that broader title memory cannot work. Full-slice gains need unexamined G/H native tests, actual compact code/assets and warmed production confirmation before promotion.
